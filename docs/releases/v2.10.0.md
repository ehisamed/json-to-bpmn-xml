# v2.10.0 — Reverse import of data and artifacts

`importBpmn(xml)` now restores top-level `DataStoreReference` and `DataObjectReference` elements, simple activity data input/output associations, text annotations, groups, and artifact associations into the existing JSON model. Ordinary empty subprocesses are kept as nodes, preserving their connected sequence flows.

The importer remains a safe projection, not a lossless BPMN editor. Advanced data mappings and unsupported metadata are reported as warnings and remain in the unchanged `sourceXml`. Group names/categories and BPMNDI colors/coordinates are not reconstructed from the generated BPMN XML. Ad-hoc subprocesses still require a separate model extension.

The fixture and preview coverage tests now assert that all 39 model-generated BPMN XML files import without structural warnings. The hand-written ad-hoc subprocess fixture intentionally continues to report unsupported content and dependent flow losses.
